# GitHub Pages Setup

This project deploys the **job listing viewer** (`data/viewer/`) as a static site via GitHub Actions.

## Live demo URL

```
https://<github-username>.github.io/<repo-name>/
```

For this repository:

**https://acimdamero.github.io/ausbildung-scraper/**

## What gets published

| Published | Not published |
|-----------|---------------|
| `data/viewer/index.html` (embedded listing data) | `data/bewerbung/` (private Bewerbung UI) |
| Static CSS/JS in viewer | `bewerbung_enriched.json` |
| | Applicant profile |

The viewer contains **public job listings** scraped from employer portals — no applicant PII.

## Enable Pages (one-time)

1. GitHub repo → **Settings** → **Pages**
2. **Build and deployment** → Source: **GitHub Actions**
3. Push to `main` or merge PR — workflow `.github/workflows/pages.yml` runs automatically
4. Wait ~1–2 minutes; site appears at the URL above

## Manual deploy trigger

```bash
git push origin main
# or re-run workflow: Actions → Deploy GitHub Pages → Re-run
```

## Local preview (same as production)

```bash
python scripts/generate_viewer.py
python -m http.server 8765 --directory data/viewer
# open http://localhost:8765
```

## Sharing with others

Share the Pages URL for:

- Portfolio / CV link ("6,850+ FI apprenticeship listings aggregated")
- Helpers reviewing **job search coverage** (not personal letters)

For Bewerbung letter review, share the **local demo** instead:

```bash
open data/public/bewerbung-demo/index.html
```

Or run a local server and send a screen recording — do not upload real letters to Pages.

## Custom domain (optional)

Settings → Pages → Custom domain → add DNS CNAME to `<username>.github.io`.

## Workflow file

Located at `.github/workflows/pages.yml`. It:

1. Checks out the repository
2. Uploads `data/viewer/` as Pages artifact
3. Deploys to `github-pages` environment

No build step required — viewer HTML is pre-generated by `scripts/generate_viewer.py`.
